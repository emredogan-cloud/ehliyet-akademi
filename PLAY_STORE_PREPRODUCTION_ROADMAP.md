**Four corrections and three new findings resulted.** This is the "an audit finding is a hypothesis
until the code confirms it" rule applied to my own earlier work.

### New findings not present in any prior report

| ID     | Severity | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **N1** | **P0**   | **Subscription products do not exist in the server catalogue.** The mobile app sells `premium-haftalik`, `premium-aylik` and `komple-ehliyet`. `apps/web/lib/products.ts` `MOBILE_PRODUCTS` contains **only** `komple-ehliyet`. `anyProductById()` therefore returns `undefined` for either subscription and `/api/iap/validate` answers **404 "Ürün bulunamadı."** A user who buys weekly or monthly pays Google and receives **no server-side entitlement** — no cross-device sync, no restore, no record. Local access still opens because `grantFromStore()` writes to the device store first, which is why this was never noticed. |
| **N2** | **P1**   | **Catalogue price is wrong and is persisted.** `MOBILE_PRODUCTS[0].priceTRY = 399`; the store charges **479,99**. The route writes `priceTRY: product.priceTRY` into `purchases`, so every lifetime purchase is recorded at the wrong price. This is the "docs say 399" discrepancy in `PROJECT_STATUS.md` §5 P1-4 — but it is not only a docs problem, it is in the database write path.                                                                                                                                                                                                                                               |
| **N3** | **P1**   | **Outcome guarantee in the live web catalogue.** `apps/web/lib/products.ts:71` — the `komple-b` product lists the feature **"Geçme garantisi kapsamı"** (_pass-guarantee coverage_). This renders on the live web paywall. It is an outcome guarantee of exactly the class Play's Misrepresentation policy and Turkish consumer law both target.                                                                                                                                                                                                                                                                                        |
